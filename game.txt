Here is a detailed copy-paste prompt.

Build a production-quality browser-based multiplayer corporate HR team-building game called **“Fastest Finger: Guess the Person”**. The game combines a “Guess the Person” clue game with a real-time “Fastest Finger” buzzer system. It should be designed for global software-company teams and completed in approximately 10–15 minutes per session. The experience must be fun, professional, simple to understand, responsive, and polished.

## 1. CORE GAME CONCEPT

Players join a private game room using a short room code. Before the game starts, every player submits 3–5 fun, non-sensitive facts about themselves. The host starts the game. The system randomly selects one participant as the person to guess. The selected person’s submitted facts become clues.

Each round:

1. Display “WHO IS THIS PERSON?”
2. Reveal clues progressively.
3. Host opens the buzzer.
4. Players press a large BUZZ button.
5. Record the exact server-side order in which players buzzed.
6. The fastest player gets the first opportunity to guess.
7. Show the list of possible players.
8. Player selects their answer.
9. If correct, award points based on how early the clue was revealed and how quickly they buzzed.
10. If incorrect, apply a small penalty and allow the next eligible fastest player to guess.
11. Reveal the correct person.
12. Show a short result animation and leaderboard.
13. Continue to the next round.

Default game: 10 rounds.

Implement two roles:

## 6. FASTEST FINGER SYSTEM

This is the most important feature.

Display a large button:

“🔴 BUZZ!”

Before activation:

“WAIT FOR THE BUZZER…”

When activated:

“BUZZ NOW!”

The backend must accept the first valid buzz requests and record their server-side order.

Example:

1. Sarah — 10:42:03.182
2. Vamshi — 10:42:03.247
3. John — 10:42:03.401

The server decides the order.

Do NOT determine the winner using:

* browser timestamps
* client timestamps
* animation timing
* local JavaScript timers

After buzzing:

* Disable the player’s buzzer.
* Show “You buzzed!”
* Show their position.
* The first eligible player receives the first guess opportunity.

Prevent duplicate buzz requests.

## 7. GUESSING SYSTEM

After a player buzzes first:

Show:

“You buzzed first! Who do you think it is?”

Display player names as selectable cards.

Example:

Sarah
John
Alex
Priya
David

The guessing player gets 5–10 seconds to answer.

If correct:

* Award points.
* End the round.

If incorrect:

* Deduct penalty points.
* Mark that player as ineligible for the current round.
* Give the guessing opportunity to the next fastest eligible player.

Continue until:

* Someone answers correctly, OR
* All eligible players answer incorrectly, OR
* The round timeout expires.

The target person should not be allowed to buzz for their own round.
